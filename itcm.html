IT Call Monitoring (ITCM)

Ticketing, escalations, email notifications, and reporting

🚀 Overview

▼

What is IT Call Monitoring?

IT Call Monitoring (ITCM) is the built-in helpdesk/ticketing module in YIMS. It records IT calls, assigns tickets, tracks status and idle time, and provides history for auditing and reporting.

Tickets

Create and manage tickets from Pending to Solved.

Assignments

Assign tickets to IT employees for ownership and tracking.

Escalation

Highlight and escalate idle tickets so nothing is missed.

Email

Notify stakeholders on new tickets, updates, reminders, and escalations.

Tip: If a technician shows “(no account)” in the app, create a linked user account in Account Management so they can be assigned and tracked properly.

📊 Dashboard

▼

Key Metrics

The Dashboard provides a quick view of workload and problem areas.

  • Open / Pending / In Progress / Escalated: workload counters
  • Avg resolution: average completion time (by selected period)
  • Requires attention: items that need follow-up

🎫 Tickets

▼

Create New Ticket

  1. Select Company, Department, and optional Branch.
  2. Enter Caller Name and describe the Technical Problem.
  3. (Optional) Add Initial Troubleshooting / Notes.
  4. (Optional) Set custom escalation thresholds using Set escalation.
  5. Click Create Ticket.

Ticket List & Filters

Use filters and status tabs to find the tickets you need to work on.

Tip: Start with Unassigned to quickly claim tickets that have no owner.

Pending Case Details

Open a ticket row to see case details and take action.

🧾 Ticket Details

▼

Notes & History

Ticket Details shows the issue summary, assignee, and full audit trail.

  • Notes: log updates and troubleshooting steps
  • History: tracks important changes (status/assignment/escalation)

Recently Solved Ticket

Use recently solved records for follow-up or reporting.

✅ Resolutions

▼

Service vs Replacement

When resolving a ticket, record the correct outcome for reporting and inventory accuracy.

Important: Choose the correct inventory action (return to stock / for repair / out of stock) so records remain consistent.

👤 Profiles

▼

Employee Profiles

Profiles show workload and performance metrics per technician.

⚡ Escalations

▼

How escalation works

  • Tickets become escalated when they are idle beyond the configured threshold.
  • Escalated tickets can be assigned to a supervisor/manager for follow-up.
  • Email escalation can notify escalation recipients (optional).

Auto-Escalation Assignee

Admin/Developer can configure who receives escalated assignments.

Note: Some deployments support a Supervisor + Manager stage (optional).

✉️ Email Notifications

▼

Setup & Rules

Configure SMTP and notification rules to send ticket updates.

  • SMTP Server / Port / SSL
  • Credentials and From Name/Email
  • Enable rules: New Ticket, Status Change, Escalation, Reminder

Templates

Templates control the email subject/body and support placeholders.

Branch/Department SMTP + Recipients (Optional)

Set different SMTP senders or recipient overrides by Branch/Department.

Email Logs

Email Log records sent/failed/skipped notifications for auditing.

🩺 Diagnostics

▼

Health & Logs

Use Diagnostics to confirm schema health and background job/email status.

  • Schema checks for required objects
  • Email/background job status and last run
  • Quick actions: Open Logs / Run SMTP Test / Refresh

📈 Reports

▼

Exporting and analysis

Reports can be filtered and exported for management updates and tracking.

🔧 Troubleshooting

▼

Common issues

  • Emails not sending: check SMTP settings, templates, and Email Logs.
  • No tickets shown: verify filters and that ITCM schema is installed.
  • Escalation not happening: check escalation settings and background job/lock status.
